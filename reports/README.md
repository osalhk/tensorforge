# Reports

Everything here is generated by scripts in `notebooks/` (fixed seed 42). Regenerate with:

```bash
.venv/bin/python notebooks/03_eda.py           # eda_summary.md, figures/eda_*.png        (~30 s)
.venv/bin/python notebooks/04_experiments.py   # experiments.csv, figures/exp_*.png       (~3 min)
.venv/bin/python notebooks/06_calibrate.py     # app/calibration.json, calibration.json    (~5 s)
.venv/bin/python notebooks/05_evaluate.py      # metrics.json, classification_report.csv,
                                               # figures/eval_*.png                       (~2 min, needs model/xlmr)
```

| File | What it shows |
|---|---|
| `eda_summary.md` | Dataset facts: sizes, missing values, duplicates, class/language/channel counts, nearest-neighbour check |
| `experiments.csv` | Every experiment: TF-IDF variants (5-fold CV + validation), the 3-head baseline, XLM-R per seed and epoch, int8, final |
| `metrics.json` | Final scores of the served model and the baseline, computed through `app/model.py` (same code as `/predict`) |
| `classification_report.csv` | Precision, recall, F1 per category and team, for both models |
| `figures/eda_*.png` | Category, language, length, urgency and secondary-label distributions |
| `figures/exp_progress.png` | Validation category accuracy across the main experiments |
| `figures/exp_xlmr_training.png` | XLM-R validation accuracy per epoch for two seeds |
| `figures/eval_confusion_matrix.png` | Confusion matrix of the served model |
| `figures/eval_per_class_f1.png`, `eval_accuracy_by_language.png` | Served model vs baseline per category and per language |
| `calibration.json` | Temperature scaling: fitted temperature, calibration before vs after (5-fold held-out) |
| `figures/eval_calibration.png` | Confidence vs actual accuracy of the served (calibrated) model |

## Key findings (validation, 800 tickets)

1. **Fine-tuned XLM-R beats every classical model by 20+ points**: category accuracy 0.853 (macro-F1 0.851)
   vs 0.604 for the TF-IDF + logistic regression baseline and 0.646 for the best classical variant (linear SVM).
   All three outputs correct on 83.4% of tickets; urgent F1 0.969 (recall 0.988).
2. **Random k-fold CV on train is misleading here**: TF-IDF models score ~98% in 5-fold CV but 53-65% on
   validation. Train contains close paraphrases (a train ticket's nearest train neighbour shares its category
   82% of the time; for validation tickets only 31%). Model selection therefore uses the validation set.
3. **Character n-grams beat word n-grams** for the classical models (0.630 vs 0.527): spelling in Singlish,
   Tanglish and native scripts varies too much for whole words.
4. **Channel and subject help** a little (0.604 with them, 0.599 text only), so they are part of the model input.
5. **int8 quantisation was rejected**: it cost 3-4 points of category accuracy; the served model is fp32 ONNX.
6. **Main remaining confusions**: `payment_refund` predicted as `general_inquiry` (25 of 144), `app_technical`
   as `delivery_delay` (12 of 64), `lost_item` as `app_technical` (8 of 40). `general_inquiry` has the lowest
   precision (0.51): the model uses it as a fallback for vague tickets.
7. **By language**: XLM-R is strong across scripts (Sinhala 0.86, Tamil 0.88, English 0.88). Singlish is its
   weakest (0.79) and the only language where the TF-IDF baseline is better (0.88).
8. **The raw model was over-confident; temperature scaling fixed it.** Raw: mean confidence 0.96 vs accuracy 0.85,
   expected calibration error (ECE) 0.106. Dividing the category logits by T = 1.75 (fitted by minimum NLL; the 5
   folds pick 1.72-1.77) gives ECE 0.025 on held-out folds and mean confidence 0.87, with **no prediction changed**.
   Now 5.4% of tickets fall below the `needs_human_review` threshold (0.5); only 19% of those are correct, while
   auto-routed tickets are 89% correct. `model_version` carries the temperature (`xlmr-5e87460a8fb6-T1.75`).
9. All predictions satisfy the API consistency rules (team table, secondary differs from primary, spam rules).

Caveat: the XLM-R epoch and urgency threshold were chosen on the same validation set, so its validation scores are
slightly optimistic; the hidden test set may also differ in distribution (see `data/DATA_NOTES.md`).
